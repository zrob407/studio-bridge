Core 28 tools

Always on. Scripts, instances, selection, screenshots, camera, starting and stopping playtests, logs, batch and the Roblox docs.

  • studio_listList the Roblox Studio windows currently connected to the bridge plugin.
  • bridge_updateCheck for a newer Studio Bridge release.
  • run_luauRun Luau code inside a connected Roblox Studio window (plugin context).
  • batchRun several edit-window tools in one call and one undo step.
  • instance_findFind instances under a root by name (substring, or * and ?
  • instance_childrenList children of an instance, optionally as a tree.
  • instance_getGet properties, attributes, tags and child count of an instance.
  • instance_setSet properties, attributes and tags on one or many instances.
  • instance_createCreate instances of a class under a parent.
  • instance_deleteDelete instances (services and top-level children of game are refused).
  • instance_moveReparent instances.
  • instance_cloneClone an instance.
  • script_getRead a script's source with line numbers, optionally a line range.
  • script_setReplace the whole source of an existing script.
  • script_editApply line edits to a script.
  • script_searchSearch script sources (default whole game) for text.
  • script_validateCheck Luau syntax of a script (by path) or of a source string, without running it.
  • selection_getList what is currently selected in Studio (use it when the user says "this" or "the selected one").
  • selection_setSelect instances in Studio so the user can see them (an empty list clears the selection).
  • logs_getRead the Output log of a Studio window.
  • screenshotCapture the Roblox Studio window as an image (brings the window to the front first).
  • viewport_screenshotCapture only the 3D viewport of Studio (no panels) as an image.
  • camera_setMove the Studio editor camera (not the player camera).
  • camera_framePoint the Studio editor camera at instances so they fill the view, from a chosen angle.
  • play_startStart a play session from the edit window.
  • play_stopStop the running play session (targets the server window automatically).
  • run_testRun a test in a fresh play session and return the result.
  • roblox_docsRoblox's official documentation from create.roblox.com.

Building 22 tools

Terrain, lighting, scatter, spatial tools, effects, tweens, collision groups, bulk editing, asset search and insert, and model generation.

  • terrainEdit terrain.
  • environmentLighting and atmosphere.
  • scatterScatter copies of a model or part across an area, dropped onto whatever ground is below, into a new folder.
  • spatial_findFind places to put things.
  • spatial_checkCheck things in space.
  • spatial_mapA top-down text map or a summary of an area.
  • snap_gridSnap models or parts to a grid (position, and optionally rotation in degrees).
  • raycastCast one ray, or several with rays, through the place.
  • spatial_queryFind what is near a point or inside a box, nearest first, or measure the world bounds of an instance.
  • effectsParticle emitters, beams, trails, fire, smoke, sparkles and lights.
  • physics_groupsCollision groups.
  • tween_playPreview a tween on an instance in the edit window.
  • instance_duplicateMake many copies of a model or part.
  • instance_renameRename many instances: find and replace (plain text, or a Lua pattern with pattern: true), prefix, suffix, case (upper, lower, title) and numbering.
  • instance_pivotA model's or part's pivot point.
  • instance_bulkAct on many instances at once, chosen by paths or by root with class, nameContains and tag filters.
  • instance_infoLook around the hierarchy.
  • tag_manageCollectionService tags.
  • asset_searchSearch Roblox's free Creator Store for models, decals, audio, images, meshes, mesh parts, videos or plugins.
  • asset_insertInsert a free model by asset id.
  • generate_modelGenerate a 3D model from a text prompt (and optionally a reference image) with Roblox's own generation service in Studio, and place it in the place.
  • import_rbxmLoad a .rbxm or .rbxmx file from this computer (for example one saved by export_rbxm in another place) into the open Studio place.

UI 7 tools

Building, scaling and checking GUIs, plus the device emulator.

  • ui_buildBuild a whole GUI (or any instance tree) from one nested description.
  • ui_checkCheck the on-screen GUI of a running play session for layout problems: off-screen or clipped elements, overlapping buttons and text, text that does not fit, small text...
  • ui_autoscaleConvert a GUI from pixel Offsets to responsive Scale.
  • ui_responsive_checkCheck how a GUI lays out at different screen sizes without playtesting.
  • device_emulatorStudio's device emulator.
  • gui_snapshotList the on-screen GUI of the player in a running play session (runs in the client window automatically): path, class, text, whether it is a button or input, and its c...
  • gui_clickClick a GUI object (by path) or a screen position in the player client of a running play session, using virtual input.

Playtest 3 tools

Keyboard, mouse and character control during a playtest.

  • input_keyboardSend keyboard input to a running playtest through the edit window, which Studio Bridge brings to the front first.
  • input_mouseSend mouse input to a running playtest through the edit window, which Studio Bridge brings to the front first.
  • character_moveControl the player's character in a running playtest (it runs in the client window).

Media 8 tools

Animation and audio.

  • animation_inspectDescribe a KeyframeSequence (length, loop, priority, joints, markers, keyframe times, and with detail every pose as position, rotation in degrees, weight and easing),...
  • animation_createBuild a KeyframeSequence from a description.
  • animation_editEdit a KeyframeSequence with a list of operations: scale_time {factor}, shift_time {seconds}, reverse, delete_keyframes {times or from and to}, add_marker {time, name,...
  • animation_posePose a rig from a KeyframeSequence at a time (interpolating between keyframes) by setting its Motor6D transforms, so you can take a screenshot of the result; or reset...
  • animation_playPreview a KeyframeSequence on a rig in the edit window by driving its Motor6D joints over time.
  • animation_idsAnimation instances and their AnimationIds.
  • audio_manageSounds in the place.
  • audio_reportScan Sound instances: missing SoundId, volume 0 or above 5, sounds set to Playing, and SoundIds used more than once.

Publishing 8 tools

Uploads, audits and exports.

  • asset_uploadUpload a local file to Roblox through Open Cloud (animations as .rbxm exported with export_rbxm, models, images, audio, meshes).
  • asset_upload_batchUpload many local files to Roblox through Open Cloud, one at a time, without waiting on each, then check them all in one polling pass.
  • asset_batch_statusFinish checking a batch: re-polls every unfinished item of a results file written by asset_upload_batch or asset_publish_instances, updates the file, and summarizes it.
  • asset_statusCheck an Open Cloud upload by operation id (returns the asset id when done, plus the moderation state).
  • asset_key_checkCheck that an Open Cloud API key is set up (in ~/.roblox-key.txt or ROBLOX_API_KEY) and accepted by Roblox, without printing it or uploading anything.
  • asset_auditFind every asset id a game references (mesh, texture, sound, animation and other asset properties, string attributes, and ids written in script source) in the open Stu...
  • asset_publish_instancesExport instances from Studio (for example KeyframeSequences from a rig's AnimSaves folder) as separate .rbxm files and upload them all to Roblox.
  • export_rbxmSerialize instances (for example a KeyframeSequence or a model) to a binary .rbxm file saved on this computer.

Analysis 3 tools

Script, physics and audio checks.

  • script_scanScan scripts for risky code: require by asset id, loadstring, LoadAsset, getfenv/setfenv, obfuscated strings, HTTP calls, teleports, kicks, DataStore access.
  • script_dependenciesFollow require() between scripts.
  • physics_reportScan parts for physics problems: loose unanchored parts, parts below the void, oversized or tiny parts, invisible collidable parts and MeshParts without a mesh.
Paid packs add their own tools. They appear only after a license is activated. See Studio Bridge Pro.
